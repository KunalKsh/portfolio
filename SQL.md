#                  STRUCTURED QUERY LANGUAGE(SQL)



SQL- STRUCTURED QUERY LANGUAGE IS A DATABASE TOOL WHICH IS USED TO CREATE AND ACCESS DATABASE.



EXAMPLE - TABULAR DATA IS STORED IN A TABLE NAMED 'DB'



| id | name | age | location |

|  1 |  KK  | 26  |  INDIA   |

|  2 |  SM  | 26  |  INDIA   |

|  3 |  PJ  | 27  |  INDIA   |

|  4 |  ZA  | 24  |  INDIA   |

|  5 |  NS  | 27  |  INDIA   |



PROBLEM STATEMENT - GET ALL THE NAME,LOCATION \& ID WHOSE AGE IS EQUAL TO 26?

SOLUTION USING SQL - SELECT name, id, location FROM DB WHERE age = 26;



OUTPUT -

| id | name | age | location |

|  1 |  KK  | 26  |  INDIA   |

|  2 |  SM  | 26  |  INDIA   |





SQL STATEMENTS-

DDL - DATA DEFINITION LANGUAGE

DML - DATA MANIPULATION LANGUAGE

DCL - DATA CONTROL LANGUAGE



DATA DEFINITION LANGUAGE (DDL) - IT IS USED TO DEFINE THE DATABASE STRUCTURE SUCH AS TABLES.

CREATE - CREATE TABLE TABLE\_NAME(id INT PRIMARY KEY, name VARCHAR(30), email VARCHAR(200))

ALTER - ALTER TABLE TABLE\_NAME ADD COLUMN\_NAME DATATYPE

DROP - DROP COLUMN COLUMN\_NAME



DATA MANIPULATION LANGUAGE (DML) - IT IS USED TO MANIPULATE THE DATA IN RECORDS.

INSERT - INSERT INTO TABLE\_NAME(id, name, email) VALUES(01, 'KUNAL', 'kunal@example.com');

UPDATE - UPDATE TABLENAME SET email = 'kunalksh@gmail.com' WHERE ID = 1;

DELETE - DELTE FROM TABLENAME WHERE ID = 1;

SELECT - SELECT id, name FROM TABLENAME WHERE email = 'kunalksh@gmail.com';



DATA CONTROL LANGUAGE (DCL) - IT IS USED TO SET PRIVILEGES SUCH AS GRANT AND REVOKE DATABASE ACCESS PERMISSION TO THE SPECIFIC USER.

GRANT - GRANT SELECT, INSERT ON employee TO KUNAL;

REVOKE - REVOKE  INSERT ON employee FROM KUNAL;



DBMS - DATABASE MANAGEMENT SYSTEM - IT IS A PROGRAM THAT CONTROLS CREATION, MAINTENANCE, \& USE OF A DATABASE. CONSIDER IT AS A FILE MANAGER.

RDMS - RELATIONAL DATABASE MANAGAMENT SYSTEM - IT STORE THE DATA INTO COLLECTION OF TABLES, THAT IS RELATED BY COMMON FIELDS BETWEEN THE COLUMNS OF TABLE.



SQL CONSTRAINTS - CONSTRAINTS ARE USED TO SET THE RULES FOR ALL RECORDS IN THE TABLE.

NOT NULL - COLUMN MUST HAVE SOME VALUES \& CANNOT BE LEFT NULL

UNIQUE - EACH ROW \& COLUMN MUST HAVE UNIQUE VALUES NO VALUES ARE REPEATED

PRIMARY KEY -  UNIQUE IDENTITY FOR A PARTICULAR RECORD, CANNOT BE NULL \& SHOULD BE UNIQUE

FOREIGN KEY - IT IS TO ENSURE THE REFERENTIAL INTEGRITY OF DATA IN THE TABLE, \& ALSO MATCHES THE VALUE IN ONE TABLE WITH ANOTHER USING PRIMARY KEY

CHECK - TO ENSURE WHETHER THE VALUE SATISFIES THE GIVEN CONDITION



JOINS IN SQL -

INNER JOIN (SIMPLE JOIN)- RETURNS ALL THE ROWS FROM BOTH THE TABLES WHEN ATLEAST ONE COLUMN MATCHES.

--> SELECT db.name, db.id, db2.email FROM db INNER JOIN db2 ON db.id = db2.id;



LEFT JOIN (LEFT OUTER JOIN) - RETURNS ALL THE ROWS FROM THE LEFT TABLE \& MATCHING RECORD FROM RIGHT TABLE

--> SELECT db.name, db.id, db2.email, db2.location FROM db LEFT JOIN db2 ON db.id = db2.id;



RIGHT JOIN (RIGHT OUTER JOIN) - RETURNS ALL THE ROWS FROM THE RIGHT TABLE \& MATCHING RECORD FROM LEFR TABLE

--> SELECT db.name, db.id, db2.email, db2.location FROM db RIGHT JOIN db2 ON db.id = db2.id;



FULL JOIN (FULL OUTER JOIN) - RETURNS ALL WHEN THERE IS A MATCH EITHER IN THE RIGHT TABLE OR IN THE LEFT TABLE

--> SELECT db.name, db.id, db2.email, db2.location FROM db FULL JOIN db2 ON db.id = db2.id;



NORMALIZATION - IT IS THE PROCESS OF MINIMIZING REDUNDANCY \& DEPENDENCY BY ORGANIZING FIELDS \& TABLE OF A DATABASE.

DIFFERENT TYPES OF NORMALIZATION-

FIRST NORMAL FORM(1NF) - IT REMOVES ALL THE DUPLICATE COLUMNNS FROM THE TABLE. IDENTIFICATION OF UNIQUE COLUMNS.

SECOND NORMAL FORM(2NF) - CREATION OF RELATIONSHIP BETWEEN THE TABLES USING PRIMARY KEYS \& PLACING THE SUBSETS OF DATA IN SEPARATE TABLES.

THIRD NORMAL FORM(3NF) - REMOVING THE COLUMNS THAT INDEPENDENT OF PRIMARY KEY.

FOURTH NORMAL FOMR(4NF) - ENSURES THAT IT SHOULD NOT HAVE MULTIVALUED DEPENDENCIES.



AGGREGATE FUNCTIONS-

AVG() - SELECT income\_class, AVG(salary) AS AVG\_SALARY FROM table GROUP BY income\_class

2\. COUNT() - SELECT income\_class, COUNT(\*) AS total\_count FROM table GROUP BY income\_class;

3\. MAX() - SELECT income\_class, MAX(salary) AS max\_salary FROM table GROUP BY income\_class;

4\. MIN() - SELECT income\_class, MIN(salary) AS min\_salary FROM table GROUP BY income\_class;

5\. SUM() - SELECT income\_class, SUM(salary) AS sum\_salary FROM table GROUP BY income\_class;

6\. FIRST() - "WINDOW FUNCTION"

7\. LAST() - "WINDOW FUNCTION"



WINDOW FUNCTION - IT'S A SQL FUNCTION THAT PERFORMS CALCULATION ACROSS A SET OF ROWS THAT ARE RELATED TO CURRENT ROW.

ROW\_NUMBER() - ASSIGNING A ROW NUMBER WITHIN A PARTITION

RANK() - GIVE THE SAME RANK TO TIES, SKIP NUMBERS

DENSE\_RANK() - GIVE THE SAME RANK BUT DOESN'T SKIP NUMBERS

NITILE(n) - DIVIDE ROWS INTO n BUCKETS

LEAD() \& LAG() - ACCESS NEXT OR PREVIOUS ROW VALUES



INDEX - INDEX IS PERFOMANCE FINE TUNING METHOD FOR FASTER RETRIEVAL OF RECORDS FROM THE TABLE; INDEXING CREATES UNIQUE ENTRY FOR EACH VALUE

CLUSTERED INDEX - IT REORDERS THE PHYSICAL ORDER OF THE TABLE \& SEARCH BASED ON THE KEY VALUES.

NON-CLUSTERED INDEX - IT DOES NOT ALTER THE PHYSICAL ORDER OF THE TABLE \& MAINTAINS THE LOGICAL ORDER OF DATA.



PRIMARY KEY V/S UNIQUE KEY

ONLY ONE PRIMARY KEY IS POSSIBLE IN A TABLE WHEREAS WE CAN HAVE MULTIPLE UNIQUE KEY IN A TABLE.

PRIMARY KEY CANNOT HAVE A NULL VALUE WHEREAS UNIQUE MAY HAVE ONLY ONE NULL VALUE.

PRIMARY KEY SUPPORTS AUTO INCREMENT VALUE WHEREAS A UNIQUE KEY DOESN'T SUPPORT AN AUTO INCREMENT VALUE.

PRIMARY KEY IS A CLUSTERED INDEX WHERES UNIQUE KEY IS UNIQUE NON-CLUSTERED INDEX.



**ALIAS(AS)** - AN ALIAS IS A  SQL THAT ASSIGNS TEMPORARY NAMES TO THE TABLE OR THE COLUMNS OF THE TABLE, ALSO KNOWN AS CORRELATION NAME.



**COMMON TABLE EXPERSSIONS(CTE) -** IT IS A TEMPORARY TABLE THAT IS CREATED ON-THE-FLY USING WITH FUNCTION, USED IMMEDIATELY \& DISCARDED AFTER THE QUERY RUNS.

Q. SELECT UNIQUE RECORDS FROM A TABLE?

--> SELECT employee\_id, name, salary FROM employees GROUP BY employee\_id, name, salary;



Q. MAX SALARY?

--> SELECT employee\_id, name, MAX(salary) AS max\_salary FROM employees



Q. AVG \& SUM?

--> SELECT SUM(salary) AS SUM, AVG(salary) AS AVG FROM employees



Q. DELETE DUPLICATES RECORD FROM TABLE?



--> STEP 1 - ASSIGN ROW NUMBERS TO EACH UNIQUE SET OF RECORDS

    SELECT row\_id, employee\_id, name, salary,

      ROW\_NUMBER() OVER(PARTITION BY employee\_id, name, salary ORDER BY employee\_id) AS ROW\_NUMBER

    FROM employee;



--> STEP 2 - SELECT rowid OF RECORDS WITH ROW\_NUMBER>1

   SELECT rowid FROM (SELECT row\_id, employee\_id, name, salary,

                       ROW\_NUMBER() OVER(PARTITION BY employee\_id, name, salary ORDER BY employee\_id) AS ROW\_NUMBER FROM employees)

   WHERE ROW\_NUMBER > 1;



--> STEP 3 - DELETE THE RECORDS FROM THE TABLE USING rowid

 	     DELETE FROM EMPLOYEES WHERE rowid IN ( SELECT rowid FROM( SELECT rowid ROWNUMBER()

                                                                        OVER(PARTITION BY employee\_id, name, salary ORDER BY employee\_id) AS ROW\_NUMBER()

                                                                         FROM EMPLOYEES) WHERE ROWN\_NUMBER > 1);

Q. READ TOP 5 RECORDS FROM A TABLE?

--> SELECT \* FROM department WHERE ROWNUM <= 5;

    ROWNUM IS A "PSEUDOCOLUMN" THAT ASSIGNS TO EACH ROW RETURNED BY A QUERY



Q. READ LAST 5 RECORDS FROM A TABLE?

--> SELECT \* FROM department

    MINUS

    SELECT \* FROM department WHERE ROWNUM <= (SELECT COUNT(\*) - 5) FROM department



Q. FIND THE SECOND MAX SALARY?

--> WITH RANKED AS (SELECT employee\_id, name, salary, DENSE\_RANK() OVER(ORDER BY salary DESC) as rank FROM department)

    SELECT employee\_id, name, salary

    FROM RANKED

    WHERE rank <= 2;
